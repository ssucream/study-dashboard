# 예상 문제 생성 기능 검토

시험 공부용 요약 자료 + 추가 강의 자료를 바탕으로 예상 문제를 생성하고 풀어볼 수 있는
기능에 대한 실현 가능성 검토 기록.

## 요구사항 요약

- 강의 자료는 대다수 PDF / PPTX / DOCX 형식으로 제공됨.
- 요약 자료 기반 모드에서는 과목별로 시험 범위 주차를 (다중) 선택하면,
  해당 주차 내 요약본과 원본 STT 텍스트를 함께 참고해 문제를 생성.
- 문제 유형: 객관식(5지선다 1택), 단답형, 서술형 3종.
- 유형별 문제 개수는 각각 최대 20문제까지 선택 가능.
- 문제를 푼 뒤 채점 모드를 실행하면, 생성된 문제를 바탕으로 답안을 채점하고
  오답 사유를 함께 제시.
- 이 모든 기능은 AI API가 연결(설정)된 상태에서만 사용 가능해야 함.

## 1. 요약본 + STT 기반 모드 — 기존 구조 재사용 가능

- 요약본: `backend/api/summary_store.py`가 이미 과목/주차별 요약 파일을 찾는
  구조라 재사용 가능.
- STT 원본: `src/downloader/pipeline.py`의 `build_download_paths()`가
  `text/{course}/{week}/{title}.txt` 규칙으로 저장하므로, summary_store와
  동일한 패턴의 조회 함수를 하나 추가하면 "주차별 STT 원본 찾기"도 문제없음.
- 시험범위 다중 주차 선택: `courses.py`의 `get_course_detail()`이 이미
  주차 단위(`Week.week_number`, `week_label`)로 강의 목록을 내려주고 있어서,
  프론트에서 주차 체크박스만 추가하면 됨.

→ "과목 → 시험범위 주차 여러 개 선택 → 해당 주차들의 요약+STT 텍스트를 모아
LLM에 전달"은 기존 코드 재사용만으로 구현 가능.

## 2. PDF / PPTX / DOCX 강의자료 — 신규 작업 필요

- 현재 파일 업로드 API가 전혀 없음(확인 완료). 업로드 엔드포인트 + 저장 위치
  (예: `/downloads/materials/{course}/{week}/`)를 새로 만들어야 함.
- 텍스트 추출을 위해 `pypdf`(PDF), `python-pptx`(PPTX), `python-docx`(DOCX)
  의존성 추가 필요 — `pyproject.toml`에 신규 항목.
- 이미지 위주 슬라이드(텍스트가 이미지로 박혀있는 PPT)는 텍스트 추출이 안 되는
  한계가 있음 — OCR까지는 이번 스코프에서 제외하는 게 합리적.

## 3. 문제 생성 (객관식 5지선다 / 단답형 / 서술형, 유형별 최대 20개)

- `src/summarizer/summarizer.py` 패턴(Gemini/OpenAI/OpenRouter 분기 + 프롬프트
  조립)을 그대로 복제해 `src/quiz/generator.py` 같은 신규 모듈로 만들면 됨.
- 관건은 AI 응답을 채점 가능한 구조로 강제하는 것 — 자유 텍스트가 아니라
  JSON(문제/보기/정답/해설)으로 받아야 하므로, 프롬프트에 스키마를 명시하고
  파싱 실패 시 재시도하는 로직이 필요(요약 파이프라인에는 없던 부분).
- 유형별 최대 20개 × 3종 = 최대 60문제를 한 번에 생성하면 응답 토큰이 꽤
  커짐. 자료(요약+STT+업로드 자료)가 많은 주차를 여러 개 선택하면 입력
  토큰도 커지므로, 필요시 유형별로 API 호출을 나누는 것도 고려할 만함
  (품질·안정성 vs API 호출 수 트레이드오프).

## 4. 채점 모드 (정답 채점 + 오답 사유)

- 객관식: 정답을 이미 서버가 알고 있으므로 AI 호출 없이 로컬에서 즉시 채점
  가능. 오답 사유는 문제 생성 시점에 "해설"을 함께 만들어 저장해두면 채점
  때 그대로 보여주면 됨(추가 API 호출 불필요).
- 단답형/서술형: 정답이 고정된 문자열이 아니라 의미 판단이 필요하므로 AI
  채점이 필수. 문제+정답(또는 채점기준)+사용자 답안을 다시 LLM에 보내
  채점/오답사유를 받는 별도 호출이 필요함. 서술형은 특히 모델·temperature에
  따라 채점 기준이 살짝 흔들릴 수 있어, "참고용 채점"이라는 안내 문구를
  두는 게 안전함.

## 5. 전제조건 (AI API 연결 필수)

- 기존 `Config.AI_ENABLED` / `AI_AGENT` / 암호화된 API 키 체계를 그대로
  재사용하면 됨. 문제 생성·채점 버튼은 AI 미설정 시 비활성화하고
  "설정 > AI 요약"으로 안내하는 정도로 충분히 구현 가능 — 별도 신규 설정
  불필요.

## 신규로 필요한 것 정리

| 구분 | 내용 |
|---|---|
| DB | `quiz_sets`(문제셋 메타: 과목/주차범위/생성일), `quiz_questions`(문제/보기/정답/해설), `quiz_attempts`(사용자 답안/채점결과) 3개 테이블 |
| 백엔드 | `src/quiz/generator.py`(문제 생성), `src/quiz/grader.py`(주관식 채점), `backend/api/routes/quiz.py`(`/api/quiz`), 파일 업로드 라우트 |
| 의존성 | `pypdf`, `python-pptx`, `python-docx` |
| 프론트 | 시험범위(주차 다중선택)+자료 업로드+문제유형/개수 설정 화면, 풀이 화면, 채점 결과 화면 |

## 종합 의견

난이도는 "요약 기능 하나 더 만드는 수준"이 아니라, 문제 생성 파이프라인 +
채점 파이프라인 + 신규 문서 파싱 + 신규 DB 스키마 + 신규 UI 3~4개 화면이
결합된 중간~중상 규모 기능이다. 다만 AI 호출 부분은 기존 summarizer
인프라를 거의 그대로 재사용할 수 있어서, "새로 만드는 것"보다 "요약 기능
옆에 병렬로 하나 더 짓는" 형태에 가깝다.
