# study-dashboard

> 🇰🇷 Версия на корейском языке: [README-ko_kr.md](README-ko_kr.md)

Персональный учебный сервис, который автоматически воспроизводит, конвертирует и
резюмирует видеолекции системы Learning X Университета Сунсиль (canvas.ssu.ac.kr),
а затем позволяет просматривать их в веб-панели в формате Markdown с разбивкой по
семестрам / предметам / неделям.

---

## Поток экранов

```
Вход в систему (учётная запись Learning X)
  └── Главная панель управления
        ├── [Переключатель автоматического режима ВКЛ/ВЫКЛ]
        │     ├── (ВКЛ)  Отображение статуса лекции, воспроизводимой в данный момент
        │     └── (ВКЛ)  Отображение времени следующего запланированного запуска
        └── Выбор семестра  (напр.: 1-й семестр 2026 / 2-й семестр 2026)
              └── Список предметов
                    └── Конспект лекций по неделям  (рендеринг Markdown)
```

## Конвейер автоматизации

```
Фоновое воспроизведение видеолекции → STT через Whisper → Резюме от ИИ → Сохранение в Markdown → Просмотр в вебе
```

| Возможность | Описание |
|------|------|

## Главная панель управления

На главной странице, которая отображается после входа, можно просматривать
следующую информацию и управлять ею.

### Переключатель автоматического режима

| Состояние | Поведение |
|------|------|
| ВЫКЛ | Автоматический запуск отсутствует. Доступны только навигация по семестрам и предметам и просмотр конспектов |
| ВКЛ | Начинается автоматическая обработка непросмотренных лекций по заданному расписанию |

### Информация, отображаемая при включённом автоматическом режиме

- **Лекция, воспроизводимая в данный момент** — название предмета, название лекции, этап конвейера (`Воспроизведение` / `Преобразование STT` / `Резюмирование`)
- **Следующий запуск по расписанию** — время следующего автоматического запуска и количество лекций к обработке

> Значения расписания автоматического режима по умолчанию: KST 09:00 / 13:00 / 18:00 / 23:00

## Установка и запуск

Заранее собранные образы загружаются из Docker Hub и запускаются. **Клонировать
репозиторий не требуется.** Достаточно одного файла `docker-compose.yml`,
прикреплённого к релизу.

### 1. Создание рабочей папки + загрузка файла compose

```bash
mkdir study-dashboard && cd study-dashboard

curl -LO https://github.com/ssucream/study-dashboard/releases/latest/download/docker-compose.yml
```

> Если `curl` отсутствует, скачайте `docker-compose.yml` вручную со
> [страницы последнего релиза](https://github.com/ssucream/study-dashboard/releases/latest)
> и положите его в эту папку.

### 2. Генерация локального сертификата HTTPS (один раз при первом запуске)

Создаётся самоподписанный сертификат для доступа из браузера.

```bash
mkdir -p certs
openssl req -x509 -nodes -newkey rsa:2048 -sha256 -days 825 \
  -keyout certs/local.key -out certs/local.crt \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
```

### 3. Запуск

```bash
docker compose pull
docker compose up -d
```

### 4. Доступ

Откройте в браузере **<https://localhost:3443>**.
Поскольку сертификат самоподписанный, браузер покажет предупреждение — перейдите
по пути «Дополнительно → Продолжить».

После входа с учётной записью Learning X учётные данные, API-ключ для резюме от ИИ
и параметры загрузки / STT / Telegram сохраняются на экране **Настройки**
веб-панели.

> При доступе к `http://localhost:3000` происходит автоматическое перенаправление
> на HTTPS (`3443`).
> Backend API (`127.0.0.1:8000`) открыт только для локальной проверки
> работоспособности, а трафик браузера проходит через HTTPS nginx.

Значения настроек, загруженные файлы, ключ шифрования и сертификаты сохраняются в
папках `db/`, `downloads/`, `logs/`, файле `.secret_key` и папке `certs/`
рабочей папки, поэтому они сохраняются даже при остановке и повторном запуске
контейнера.

### Обновление / остановка

```bash
docker compose pull && docker compose up -d   # Обновление до последней версии
docker compose down                           # Остановка (данные сохраняются)
docker compose down -v                         # Остановка + удаление томов с кэшем
```

## Для разработчиков — запуск со сборкой из исходников

При разработке с прямым изменением исходников склонируйте репозиторий, затем
удалите строку `image:` в `docker-compose.yml` и раскомментируйте расположенную
непосредственно под ней закомментированную секцию `build:` (а также монтирование
томов с исходниками).

```bash
git clone https://github.com/ssucream/study-dashboard.git
cd study-dashboard
./scripts/generate-local-cert.sh          # Генерация сертификата HTTPS
# После замены image: → build: в docker-compose.yml и раскомментирования монтирования томов с исходниками
docker compose up --build
```

Адрес доступа тот же, что и для развёртывания — **<https://localhost:3443>**.

## Хранилище настроек

Этот проект не использует файл `.env`. Настройки хранятся в БД SQLite
(`db/app.db`). Номер студента и пароль не сохраняются в БД во избежание
автоматического входа и хранятся только в памяти текущей сессии, а API-ключи и
токены Telegram хранятся в БД в зашифрованном виде.

При запуске через Docker путь загрузки фиксирован как `/downloads` внутри
контейнера. Конфигурация compose по умолчанию монтирует папку `./downloads`
рабочей папки в `/downloads` контейнера.

### Размер модели Whisper

faster-whisper применяет квантование INT8, поэтому размер файла модели примерно
вдвое меньше по сравнению с openai-whisper.

| Модель | Размер (INT8) | Точность |
|------|------------|--------|
| tiny | ~39 МБ | Низкая |
| base | ~74 МБ | Средняя (по умолчанию) |
| small | ~122 МБ | Хорошая |
| medium | ~385 МБ | Высокая |
| large | ~750 МБ | Наивысшая |
